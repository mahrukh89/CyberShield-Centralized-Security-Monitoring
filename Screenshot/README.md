# 📸 Visual Evidence & Project Dashboards

This directory contains high-impact visual evidence demonstrating the execution of the **Wazuh SIEM Enterprise Implementation** project.

Rather than overwhelming viewers with low-value screenshots of basic text tables, this repository follows a **hybrid evidence model**:

1. **Interactive Tool UI & Data Visualizations** are captured here as high-resolution screenshots (`01`–`05`).
2. **Quantitative & Governance Control Files** are maintained as editable spreadsheets (`.xlsx`) and structured Markdown (`.md`) files across their respective repository folders.

---

## 📑 Core Evidence Gallery

### `01-work-breakdown-structure.png`

* **Artifact Type:** Work Breakdown Structure (WBS)
* **Tool Used:** Draw.io / Flowchart Engine
* **Purpose:** Demonstrates the visual decomposition of the project into Level 2 technical work packages, including Wazuh Manager installation, Sysmon log collection, rule tuning, and SOC playbooks.

---

### `02-gantt-chart.png`

* **Artifact Type:** Project Timeline & Schedule
* **Tool Used:** Jira Timeline / Gantt View
* **Purpose:** Displays phased sprint execution, milestone markers, task sequencing, and critical-path dependencies throughout the project lifecycle.

---

### `03-jira-board.png`

* **Artifact Type:** Agile Sprint Kanban Board
* **Tool Used:** Jira Software
* **Purpose:** Highlights task movement across workflow stages:

`Backlog` → `To Do` → `In Progress` → `Review/Testing` → `Done`

The board also demonstrates assigned epics and clear task ownership.

---

### `04-project-dashboard.png`

* **Artifact Type:** Executive KPI Dashboard
* **Tool Used:** Jira Dashboards / Performance Gadgets
* **Purpose:** Provides an at-a-glance overview of project performance, including sprint velocity, log-source onboarding progress, open defect tracking, and scope completion rates.

---

### `05-risk-matrix.png`

* **Artifact Type:** 3×3 Risk Exposure Heatmap
* **Tool Used:** Excel / Google Sheets Visual Matrix
* **Purpose:** Visually maps active project risks based on **Probability (1–5)** and **Impact (1–5)** to support proactive risk mitigation and project decision-making.

## 🔒 Screenshot Quality & Privacy Standards

* **No Sensitive Data Exposure:** Internal IP addresses, API tokens, passwords, credentials, and sensitive system telemetry have been sanitized or omitted.
* **Clean Presentation:** Screenshots are tightly cropped to remove unnecessary browser tabs, bookmark bars, operating system pop-ups, and other irrelevant elements.
* **Project Relevance:** Each screenshot is included as supporting evidence for a specific project activity, deliverable, or management control.
