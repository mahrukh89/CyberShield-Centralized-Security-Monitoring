## Executive Overview

This repository presents a complete **cybersecurity project management lifecycle** for a simulated enterprise security monitoring implementation.

The project demonstrates how a Project Coordinator / Junior Project Manager can structure, plan, execute, monitor, control, and formally close a cybersecurity initiative using professional project-management practices.

### Project Scenario

**Project:** CyberShield Centralized Security Monitoring Implementation

A fictional organization wants to improve security visibility by centralizing priority security telemetry, establishing detection and incident workflows, creating management reporting, and preparing the operational team for handover.

The project uses a **hybrid delivery model**: predictive planning for governance, scope and milestones, combined with sprint-based execution for technical delivery.

### Portfolio Objective

Demonstrate practical capability across:

* Project initiation
* Requirements management
* Scope management
* Work Breakdown Structure (WBS)
* Scheduling and Gantt planning
* Stakeholder management
* RACI/accountability
* Risk and RAID management
* Communications
* Jira-style execution
* Sprint planning
* Meeting governance
* Status reporting
* KPI/dashboard monitoring
* Change management
* Project closure
* Lessons learned

## Business Problem

The fictional organization has security telemetry distributed across endpoints, identity systems, cloud services and network infrastructure.

This creates:

* Fragmented security visibility
* Slow investigation
* Inconsistent escalation
* Manual reporting
* Unclear ownership
* Difficulty measuring security operations

## Business Objective

Establish a centralized security-monitoring capability with:

1. Priority log-source visibility
2. Defined detection requirements
3. Alert triage and escalation workflows
4. Management dashboards
5. Operational documentation
6. Stakeholder training
7. Formal handover and governance

# 6\. PM Framework Demonstrated

## Initiation

The project begins with a business problem, sponsor, objective, success criteria, assumptions and constraints.

## Planning

The project is translated into manageable deliverables through requirements, scope, WBS, schedule, stakeholders, RACI, communications and risk planning.

## Execution

Work is organized into epics, tasks and sprints. Delivery is tracked through a Jira-style workflow.

## Monitoring \& Control

Project health is monitored through:

* Status reporting
* RAG indicators
* KPI tracking
* RAID management
* Risk reviews
* Dependency tracking
* Change control

## Closure

The project closes through formal acceptance, operational handover, documentation, closure reporting and lessons learned.

# 9\. Risk Governance

Risk scoring follows:

```text
Risk Score = Probability × Impact
```

|Score|Treatment|
|-:|-|
|1–4|Low|
|5–9|Moderate|
|10–14|High|
|15–25|Critical|

High and critical risks receive active response plans and are reviewed through project governance.

\---

# 10\. Change Management

All material changes are assessed for:

* Scope impact
* Schedule impact
* Cost impact
* Resource impact
* Quality impact
* Risk impact

A change becomes part of the approved baseline only after appropriate authorization.
