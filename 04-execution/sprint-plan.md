# Sprint Plan

## Delivery Model

Four two-week delivery sprints are used within the wider 12-week project lifecycle.

## Sprint 1 — Foundation

**Goal:** Establish requirements, governance and implementation readiness.

### Planned Work
- Requirements validation
- Stakeholder confirmation
- Dependency identification
- Initial backlog
- Acceptance criteria
- Architecture review

### Definition of Done
- Requirements approved
- Dependencies documented
- Backlog prioritized
- Sprint review completed

## Sprint 2 — Implementation

**Goal:** Onboard priority sources and establish the initial monitoring capability.

### Planned Work
- Source onboarding
- Detection configuration
- Dashboard configuration
- Alert workflow
- Technical validation

## Sprint 3 — Validation

**Goal:** Validate functionality and prepare for UAT.

### Planned Work
- Detection testing
- Defect resolution
- UAT preparation
- Documentation
- Operational review

## Sprint 4 — Handover

**Goal:** Complete UAT, training and operational transition.

### Planned Work
- UAT
- Training
- Runbook finalization
- Handover
- Sponsor acceptance
